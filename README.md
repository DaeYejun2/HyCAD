# HyCAD — 구현과 재현 절차

컨테이너 레플리카를 서로 비교해 감염된 레플리카를 지목하고, 정상 기준선과 비교해
전원 감염까지 다루는 이상 탐지 시스템. 논문(KSC2026)의 실험이 이 코드로 돌아간다.

---

## 1. 파일 구성

| 파일 | 역할 |
|---|---|
| `manifest.py` | 캡처 16종의 경로 · 공격 시각 · 감염 레플리카 · 정답 라벨 |
| `preprocess.py` | `jsonl.gz` -> (스냅샷, 레플리카) 집계 pickle |
| `channels.py` | 채널 A / B / C, 비교용 RW(Jaccard) · TV  |
| `controller.py` | 임계값 보정 + 판정 규칙 |
| `evaluate.py` | 표 재생성 |
| `compare.py` | ReplicaWatcher · CDL 과의 대조 |
| `closed_loop.py` | 닫힌 고리(자동 재학습) 시뮬레이션 |
| `cache/` | 전처리 결과. `preprocess.py --all` 이 채운다 |

의존성은 `numpy` 뿐이다. 채널 B 를 오토인코더로 쓰려면 `torch` 가 더 필요하다
(`UCBADX_B=ae` 환경변수).

---

## 2. 실행

```bash
cd ucbadx

python preprocess.py --all      # 캡처 16종, 약 1억 이벤트. 15~20분
python evaluate.py              # 전체 표
python compare.py               # RW · CDL 대조
python closed_loop.py           # 닫힌 고리
```

`evaluate.py` 는 부분 실행을 받는다.

```
identify     식별 역전
attenuation  감쇠 법칙
hidden       신원 은닉 공격
channelc     C 채널
controller   판정 전 시나리오
```

캡처 파일이 없으면 건너뛰고 경고만 낸다. 개별 처리도 된다.

```bash
python preprocess.py ../caps/recon_1of4/normal_catalogue.jsonl.gz cache/recon_1of4.pkl
```

Windows 콘솔은 cp949 라 한글이 깨진다. `PYTHONIOENCODING=utf-8` 을 붙일 것.

## 3. 데이터

캡처는 `rw/tools/capture2.sh` 형식이다. 직접 뜨려면 12개 필드만 기록한다.

```bash
sysdig -j -p'*%evt.rawtime %container.name %evt.type %evt.category
             %fd.directory %fd.filename %fd.type
             %proc.name %proc.cmdline %proc.cwd %proc.exe %proc.args' \
       "container.name contains <접두어>" | gzip > capture.jsonl.gz
```

| key | 내용 |
|---|---|
| `cat_baseline` | catalogue 정상 100분 (200 스냅샷). 임계값 보정용 |
| `cat_1of4` ~ `cat_4of4` | XMRig 크립토마이닝, 감염 1~4개, 각 30분 |
| `recon_1of4` ~ `recon_4of4` | 정찰 명령 반복, 감염 1~4개 |
| `fe_n4_norm` / `fe_n4_hidden` | Node 4.8 정상 / 신원 은닉 채굴 |
| `fe_n10_norm` / `fe_n10_hidden` | Node 10.24 정상 / 신원 은닉 채굴 |

`fe_n10_norm` 은 **자기 배포 기준으로는 정상**이고 `fe_n4_norm` 기준으로 보면
실제 드리프트다(신규 syscall 5종, 구성비 TV 0.2046). 드리프트 평가는
`closed_loop.py` 가 Node 4 기준으로 수행한다.

## 4. 모델

### 채널

| 채널 | 정의 | 보는 것 |
|---|---|---|
| **A** | `mean_j \|Ri \ Rj\| / \|Ri\|` (10개 집합 특성, L2 합산) | 누가 남들에게 없는 원소를 갖고 있나 |
| **B** | 정상 기준 구성비 대비 차원별 z 점수의 최댓값, 정족수 25% | 평소의 자기와 다른가 |
| **C** | `\|log2( (총 이벤트 / accept 수) / 기준값 )\|` | 요청 하나에 드는 일이 변했나 |

A 는 **비대칭**이다. 대칭 지표(Jaccard, TV)는 과반 감염에서 순위가 뒤집힌다.
A 는 레플리카마다 값을 내고, B 와 C 는 서비스 단위로 하나를 낸다.

### 판정

```
A 지목 있음                    -> 부분 감염   (지목된 집합 출력)
A 침묵 · B 정상                -> 정상       (학습 버퍼에 적립)
A 침묵 · B 이상 · C 변동        -> 전원 감염
A 침묵 · B 이상 · C 안정        -> 정상 변화   (B · w_ref 재학습)
```

순서가 고정이다. A 의 침묵이 먼저 확보돼야 B 의 신호가 "전원이 균일하게 변했다"는
뜻이 된다.

### 임계값

정상 baseline 만 보고 정한다. 공격 데이터는 쓰지 않는다.

| | 계수 | catalogue | front-end(N4) | front-end(N10) |
|---|---|---|---|---|
| θ_A | 정상 최댓값 × 2.00 | 0.1429 | 0.1720 | 0.1333 |
| θ_B | 정상 최댓값 | 11.57 | 6.142 | 8.475 |
| θ_C | **절대값 0.20** | 공통 | 공통 | 공통 |
| w_ref | 정상 중앙값 | 53.5 | 55.5 | 50.6 |

θ_C 는 **2026-09-16 에 0.30 에서 0.20 으로 내렸다.** 결과를 보고 정한 값이며,
바꾼 뒤 Docker · k8s 양쪽을 재실행해 나빠진 칸이 없음을 확인했다.

## 5. 자동 재학습 조건

세 가지가 **모두** 만족돼야 한다.

1. **변화가 전 레플리카에 균일** — A 가 침묵해야 한다. 한 레플리카만 달라지면
   "부분 감염"으로 처리되고 재학습하지 않는다. *(의도된 동작)*
2. **요청당 작업량 변화 < θ_C** — C 가 안정이어야 한다. 크게 변하면 "전원 감염"으로
   처리된다. *(공격 오염 방지 장치)*
3. **20 스냅샷(10분) 연속 유지** — 후보 버퍼가 차야 한다. 중간에 다른 판정이 끼면
   리셋된다.

> **3번에서 한 번 실패했다.** C 를 *총 이벤트 수*로 정의했을 때 실제 드리프트
> (이벤트 −9%)가 정상 변동(±6.6%)과 겹쳐 판정이 `정상 변화` ↔ `전원 감염` 을 오갔고,
> 버퍼가 계속 리셋돼 **재학습 0회**가 됐다. C 를 *요청당 작업량*으로 바꿔 해결했다.
> `channels.work_rate()` 주석 참조.
