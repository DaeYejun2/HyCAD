# 이상 의심 사건과 조사 자료 보존

화면의 `partial_infection` 표기는 **부분 이상 의심**이다. 연구 판정 코드와 A/B/C 계산·임계값은 유지한다. 감염이 확인됐다는 뜻이 아니다. 지목된 레플리카마다 사건 ID, A 점수·기준, 동료와 달랐던 특성, 연속 관측 시간·창 수와 마지막 상태를 기록한다.

## 지속 여부

연속된 유효 30초 창에서 같은 레플리카가 지목된 경우만 관측 시간을 합산한다. 다음 유효 창에서 지목되지 않으면 **지목 해제**, 불완전 창·시간 공백이면 **관측 중단 · 지속 여부 미확인**이다. 지목 해제는 공격 부재를 입증하지 않는다. 탐지기 상태는 별도 `incident-state` 볼륨에 보관해 재시작 후 공백을 정상 복귀로 표시하지 않는다. 표는 선택 기간의 사건별 마지막 기록이므로 최종 관측 시각과 상단 입력 상태도 확인한다. 조회한 최근 1,000건의 사건 갱신 범위를 사용한다.

Grafana의 사건 표는 Loki의 `hycad-incidents`를, 보존 표는 `hycad-evidence`를 읽는다. 과거 설명의 ‘부분 감염’ 문구는 요약 표시에서만 바꾸고 저장된 원문·점수를 덮어쓰지 않는다. 원본 JSON 상세에는 과거 문구가 남을 수 있다. 기존 사건에는 지속 시간이나 새 연결 필드를 소급 생성하지 않는다.

## 저장되는 조사 자료

`hycad-evidence.service`는 모니터 호스트에서 동작하는 별도 Python 서비스다. 탐지기의 최신 유효 LIVE 판정을 확인해 부분/전체 이상에 대해서만 보존한다. 최초 지목 구간 **시작 60초 전부터 끝 60초 후**까지를 대상으로 한다. 지속 이상은 같은 사건에 대해 120초마다 새 체크포인트를 만든다. drift나 replay는 운영 원본 보존을 유발하지 않는다.

실제 보관 위치는 `/var/snap/docker/common/hycad/evidence/incident-.../`이다. `hycad:hycad-data` 소유 디렉터리 `0700`, 파일 `0600`으로 두며 Grafana·탐지기에는 원문 디렉터리를 마운트하지 않는다. 코드 저장소·Mac 코드 백업에는 포함하지 않는다.

- `manifest.json`: 요청 구간, 실제 관측 범위, 대상·기준선 해시·판정 원문, 보존 상태·누락·한도, 파일 SHA-256.
- `events-before-and-trigger.jsonl.gz`, `events-after.jsonl.gz`: 제한된 시각 범위의 원본 Sysdig JSON. 압축 전 각 128MiB까지.
- `connections-before.json`, `connections-after.json`: 프로세스 PID/PPID, 컨테이너, 시스템콜 진입/복귀·반환값, 로컬/원격·클라이언트/서버 IP와 포트. 각 파일 최대 1,000개 조합을 요약하며 원문은 이벤트 파일에 있다.
- `service-context.json`: catalogue 4개와 catalogue-db의 Docker stdout/stderr, 컨테이너·이미지 식별자, 시작 시각·재시작 횟수·네트워크 주소. 환경변수와 Docker 명령행은 읽지 않는다. 로그는 컨테이너당 최근 2,000줄·2MiB·명령당 8초로 제한하고 적용 여부를 기록한다.

`fd.rip`/`fd.rport`는 관측된 소켓의 원격 상대이며 호출 방향·결과와 함께 해석한다. 모든 값이 공격 목적지나 성공한 연결을 뜻하지 않는다. 연결 실패나 커널 추적 시점에 따라 주소가 비어 있을 수 있다. 서비스가 stdout/stderr에 출력하지 않은 요청은 Docker 로그에서 복원되지 않는다. HTTPS 본문·전체 네트워크 패킷을 수집하는 기능은 아니다. 필드 의미는 [Sysdig User Guide](https://github.com/draios/sysdig/wiki/Sysdig%20User%20Guide)를 따른다.

모델 입력 필드 12개·필터는 유지하고 조사 전용 필드를 추가했다. PID/IP/포트는 모델 특성이나 Prometheus 라벨에 넣지 않는다. 원문에는 기존 명령행·내부 주소·서비스 출력이 포함될 수 있으므로 공유 전에 별도 검토한다. Grafana에는 사건 ID·근거·보존 상태만 표시한다.

## 권한과 한도

수집 SSH 키는 기존 무인자 캡처 래퍼에만 사용한다. 별도 `/etc/hycad/context_ed25519` 키는 대상 VM의 root 소유 `hycad-context-catalogue` 고정 래퍼만 실행한다. 요청은 표준입력의 숫자 start/end이며, 최근 1시간 안의 최대 600초 범위만 허용한다. 컨테이너 목록은 서버 코드에 고정하고 셸 명령이나 사용자 지정 경로를 받지 않는다. 키에 일반 셸·포워딩 권한을 주지 않는다.

동시에 최대 4건을 대기시키고 디스크 여유가 1GiB 미만이면 새 작업을 거부한다. 압축된 사건 자료는 최대 7일·총 5GiB를 목표로 오래된 완료 건부터 정리하며, 진행 중 작업의 최대 용량을 미리 확보하도록 완료 건 한도를 줄인다. 디렉터리를 보존 기간 밖으로 수동 복사하면 자동 정리 범위에서 제외된다. 보존 상태 파일 `live/evidence-health.json`은 비밀 없는 메타데이터만 포함하고 탐지기가 읽어 `hycad_evidence_ready`를 제공한다.

원본 회전 파일의 실제 과거 범위가 부족하거나 크기 한도에 도달하면 `limited`로 기록한다. 파일 내 단절 표식은 요청 구간 밖의 표식일 수도 있어 보수적으로 표시한다. `complete`는 관측 경계·설정 한도·로그 요청 검사가 통과했다는 뜻이며 커널 이벤트 무손실이나 공격 원인 확정을 보증하지 않는다. 보존 서비스 재시작 중이던 작업은 `interrupted`로 남긴다. 서비스가 꺼져 있던 동안 이미 덮어쓴 원본은 복원하지 못한다.

## 설치·검증

대상 VM에는 `deployment/capture/serve_capture.py`, `serve_context.py`, `hycad-context-catalogue`를 root 소유로 설치한다. 새 공개키는 `restrict`, 모니터 호스트 주소 제한, 무인자 sudo 고정 명령으로 등록한다. sudoers는 해당 무인자 래퍼만 허용한다. 원본 수집기 재연결은 필드 추가 적용 때문에 한 번 필요하며 그때의 불완전 창은 유보된다.

모니터 호스트에는 기존 서비스와 함께 `deployment/systemd/snap/hycad-evidence.service`를 설치한다. 일반 Docker 호스트에는 상위 디렉터리의 템플릿을 쓴다. 보존 서비스에만 조사 키를 주며 탐지 컨테이너에는 SSH 키를 전달하지 않는다.

```bash
sudo systemctl enable --now hycad-evidence.service
sudo systemctl status hycad-evidence.service --no-pager
sudo journalctl -u hycad-evidence.service -n 50 --no-pager
sudo cat /var/snap/docker/common/hycad/evidence/health.json
```

조사는 manifest의 SHA-256·실제 관측 구간·한도부터 확인하고 연결 요약을 서비스 로그/컨테이너 네트워크와 대조한다. 테스트는 합성 입력으로 판정 지속·공백·한도·재시작을 확인하고, 실제 서버에서는 공격을 실행하지 않고 읽기 전용 수집·컨텍스트 보존 경로를 확인한다. 시험용 자료를 실제 공격 사건이나 자연 발생 판정으로 등록하지 않는다.

실제 Sysdig 0.41.4 출력 검증에서 `%proc.args` 뒤에 다른 필드를 붙이면 `proc.args` 대신 빈 JSON 키가 출력되는 동작을 확인했다. 따라서 추가 조사 필드는 `proc.args` 앞에 두고 이 필드를 포맷의 마지막에 유지한다. 모델 필드 집합은 동일하며, 조사 필드가 전처리·빈도에 영향을 주지 않는 회귀 검증을 유지한다.

추가 조사 필드로 늘어난 입력에 맞춰 서버 상시 수집 회전 파일은 각각 256MiB, 두 파일 합계 최대 512MiB로 설정한다. 이 버퍼는 사건 보존 5GiB와 별도이며 VM 디스크에 쓰지 않는다. 실제 시간 범위는 이벤트 발생량에 따라 달라진다.

## 판정과 사후 검토의 분리

화면의 전체 이상 의심은 모델 분류이며, 실제 A·B 임계값을 넘은 레플리카 목록을
별도로 표시한다. 현재 B 정족수는 25%이므로 4개 중 하나의 B 초과와 C 초과가
전체 지목으로 이어질 수 있다. 각 레플리카의 침해 증거가 확인됐다는 뜻이 아니다.
계산과 내부 상태값은 그대로 두고 표시·근거 정보만 추가한다.

사후 검토는 `evidence/reviews/<사건 ID>.json`에 별도로 저장한다. 분석 문장 입력은
`reviewer`, `assessment`, `attack_evidence`, `benign_evidence`, `unknowns`의
다섯 문자열이며 다음 명령으로 실제 원본 해시를 검증한 뒤 기록한다.

```bash
python3 -m hycad_monitor.investigation_reviews \
  --manifest /보존루트/사건ID/manifest.json --text /보호된위치/검토문장.json
```

검토 파일에는 판정 manifest 사본·해시, 원본 파일 해시, 기준선·코드 식별자와
검토 시각이 연결된다. 그 자체가 공격/정상의 정답 검증이나 디지털 서명은 아니다.
검토자는 확인된 관측, 정상 동작 가능성, 미확정 원인을 구분해 작성해야 한다.
새 사건은 자동으로 미분석이며 이전 사건의 오탐 해석을 전파하지 않는다.

보존 서비스는 별도 스레드에서 제한된 검토 문장을 `hycad-investigations`로 게시한다.
서비스 재시작과 한 시간마다 재게시되며 실제 검토 시각은 유지된다. 화면은 최신
게시 상태를 선택하므로 검토 파일이 잘못되거나 삭제되면 과거 결론을 계속 확정된
검토처럼 보여주지 않는다. 원본 7일/용량 보존이 끝나도 별도 검토 기록은 남으며,
화면에 원본 보존 종료 상태를 구분한다. 자동 조회 대상은 최근 ID 최대 2,000개의
보존 manifest와 최대 2,000개의 검토 파일이다. 검토 파일은 원본 정리와 별도로
관리·백업한다. 원본이나 서비스 로그 전체를 Loki에 복사하지 않는다.

IP 한 필드만으로 접속 방향을 확정하지 않는다. 실제 DB 이벤트에서 `fd.rip/lip`가
관측 프로세스 역할과 반대로 보인 사례가 있어 `fd.sip/sport`, `fd.cip/cport`,
컨테이너 네트워크 메타데이터 및 후속 송수신을 교차 확인한다.
