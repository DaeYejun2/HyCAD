# HyCAD 졸업작품 발표 실행 가이드

발표에서는 **현재 시스템콜의 LIVE 판정**과 **저장된 캡처의 재판정**을 먼저 구분한다. 화면은 두 개이며 cosmic에서 모두 실행한다. 발표용 Mac은 같은 HTTPS 주소를 여는 브라우저면 된다. 이 시연을 위해 새로운 공격을 실행하지 않는다.

이 문서는 시연 절차와 확인한 캡처 재판정 결과를 설명한다. Ubuntu 배포 후 두 대시보드의 외부 HTTPS 조회, 모드·서비스 전환과 수동 시작·일시정지·재개·배속 변경·중단·완료를 확인했다. 실제 호스트 재부팅·물리적 네트워크 단절 시험은 수행하지 않았다. 버전·결과·확인 한계는 [검증 기록](validation-2026-10-23.md)을 참고한다.

## 1. 발표 전 확인

1. [서버 운영](server-operations.md)에 따라 수집기, 두 LIVE detector, 자동·수동 재생, 두 보존기, Prometheus·Loki·Grafana·nginx를 확인한다.
2. 외부 `HYCAD_PUBLIC_URL`에서 Grafana로 로그인한다. 다른 기기에서도 같은 주소가 열리는지 확인한다. localhost 3000을 공유 주소로 사용하지 않는다.
3. LIVE에서 catalogue와 front-end를 각각 선택해 원본 창 시각이 현재로 진행하는지, 각 4개 레플리카가 관측되는지 확인한다.
4. 캡처 모드에서 사용할 승인 ID·제목·원본 시각·기준선 설명을 확인한다. 폴더명이나 시나리오 이름을 공격 성공 증거로 소개하지 않는다.
5. 수동 제어 페이지에서 다른 발표자가 진행 중인 공유 작업이 있는지 확인한다. 미리 선택한 작업을 중단하지 않고 덮어쓰지 않는다.
6. 발표 시간 범위를 이번 실행에 맞춘다. 과거 고정 시간 범위의 그래프를 현재 LIVE 상태로 읽지 않는다.

| 화면 | 경로 | 설명할 자료 |
|---|---|---|
| LIVE / 캡처 자동 순환 | `/d/hycad-overview` | 현재 2개 서비스 또는 승인 캡처별 반복 결과 |
| 캡처 수동 재생 | `/d/hycad-replay` | 발표자가 시작한 단일 캡처 결과 |
| 수동 제어 폼 | `/hycad/replay/` | 캡처·속도 선택, 시작·일시정지·재개·중단 |

세 경로는 모두 같은 외부 HTTPS 주소 뒤에 붙는다. Grafana 세션을 유지하며 접속한다. Mac의 Docker·SSH 터널·Tailscale 앱은 이 공개 조회 경로에 필요하지 않다.

## 2. 아키텍처 설명

[README의 그림](../README.md#1-전체-아키텍처)을 보며 다음 순서로 설명한다.

1. **대상 VM:** marine-normal에서 Sock Shop의 catalogue 4개와 front-end 4개가 실행된다. Sysdig가 정확히 이 8개 컨테이너의 시스템콜을 관측한다.
2. **운영 호스트:** cosmic이 제한된 SSH로 이벤트를 받고 서비스별 4개를 독립적으로 비교한다. 두 서비스를 섞어서 동료로 비교하지 않는다.
3. **모델:** 원본 이벤트를 UTC 30초 창으로 묶고 입력 품질을 검사한 뒤 고정 기준선으로 A/B/C를 판정한다.
4. **표시:** Prometheus는 수치, Loki는 판정 근거를 저장하며 Grafana가 두 자료를 조회한다. 외부 브라우저는 nginx HTTPS를 통해 접속한다.
5. **재생:** 저장 자료는 별도 worker에서 계산하므로 캡처를 선택하거나 중단해도 LIVE는 계속된다.

marine-normal은 cosmic 안의 VM이다. “정상 서버”라는 명칭을 실제로 계속 정상임이 검증됐다는 뜻으로 소개하지 않는다. 수집·모델·화면이 전부 Mac에서 실행되는 구조라고 설명하지 않는다.

## 3. LIVE 화면에서 보여줄 핵심

**서비스 → LIVE 모드 → 원본 시각 → 현재 판정 → 실제 초과 레플리카 → 짧은 근거** 순서로 본다. 기본 화면은 핵심 판단에 집중하고 필요할 때만 접힌 LIVE 조사 행을 펼친다.

| 표시 | 설명 |
|---|---|
| 입력 준비·원본 창 종료 | 지금 들어온 자료로 판정할 수 있는지 확인 |
| 판정 흐름·현재 분류 | 정상 범위, 부분/전체 이상 의심, 정상 변화 의심, 판정 불가 |
| A / 임계값 | 해당 레플리카의 집합 특성이 동료와 다른 정도 |
| B / 임계값 | 과거 기준선 대비 시스템콜 구성비의 차이 |
| C / 임계값 | accept 계열 이벤트로 정규화한 활동량의 변화 |
| 실제 A/B 초과 표 | 전체 분류와 개별 초과 레플리카를 구분 |
| 원인·지속·보존 상세 | 모델 근거와 사후 검토, 관측 공백, 조사 자료 상태 |

점수/임계값 배수 1은 경계다. 임계값이 0이면 배수 자체를 정의할 수 없어 빈 값이 생길 수 있으며 원래 점수·초과 표를 본다. B 그래프는 큰 차이를 보기 위해 로그축을 사용하므로 0도 로그축에 표시되지 않는다.

모델의 전체 이상 의심이 모든 레플리카의 B 초과를 뜻하지 않는다. B 정족수는 25%라 4개 중 1개로도 성립할 수 있다. C의 분모는 HTTP 요청 수가 아닌 accept 계열 시스템콜 이벤트 수다.

입력 누락·0 accept·불완전 창·오래된 시각은 판정 불가다. 이를 발표 편의를 위해 정상으로 바꾸지 않는다. 화면 갱신 5초와 실제 30초 판정 창을 구분한다.

## 4. 캡처 자동 순환

메인 화면에서 **캡처 재생**을 선택하고 서비스와 캡처 ID를 선택한다. 승인 캡처들이 서버에서 독립적으로 순환 중이므로 선택 순간은 파일의 처음이 아닐 수 있다. 현재 화면에서는 **원본 창 종료 시각, 캡처 설명, 기준선 설명·SHA-256**을 확인한다. 원본 전체 범위·진행률·순환 횟수는 현재 메인 대시보드에 표시하지 않는다.

자동 재생은 기본적으로 원본 30초 창을 5초마다 처리한다. 그래프 시간축은 이번 재생의 처리 시각이고 별도 원본 시각은 과거 자료의 시각이다. 과거 공격 프로그램을 다시 실행하는 기능이 아니다.

첫 창·끝 창의 판정 불가도 설명할 수 있다. 전체 30초를 실제로 관측했는지 확인할 수 없는 부분을 정상이나 이상으로 확정하지 않는 입력 품질 처리다. 재생 결과는 LIVE 이상 경보나 현재 서비스 조사 자료 보존을 시작하지 않는다.

## 5. 처음부터 수동 재생

1. 상단 **캡처 선택 · 시작/정지 · 배속** 링크로 `/hycad/replay/`를 연다.
2. 사용할 캡처를 선택하고 원본 30초 창당 2·5·10·30초 중 간격을 고른다. 발표 설명에는 5초 또는 10초부터 시작할 수 있다.
3. **처음부터 시작**을 누르면 수동 대시보드로 이동한다. 선택 캡처와 이번 실행 시간 범위가 적용됐는지 확인한다.
4. 설명할 구간에서는 제어 페이지에서 **일시정지**한다. 화면은 멈춘 작업임을 표시하며 이를 현재 정상 상태로 해석하지 않는다.
5. 속도를 바꾸려면 일시정지 상태에서 속도를 선택하고 **선택한 속도로 계속**을 누른다.
6. 다른 캡처로 바꾸려면 기존 작업을 **중단**한 뒤 새로 시작한다. 끝까지 도달하면 자동으로 반복하지 않고 재생 완료가 된다.

수동 작업은 로그인 사용자 전체가 공유하는 하나다. 발표 전에 다른 사용자의 시연과 순서를 맞춘다. 로그인·Origin·CSRF 검사 때문에 오래 열린 제어 폼이 거부되면 같은 HTTPS에서 폼을 다시 연다. 익명 접근이나 보안 설정을 끄지 않는다.

Prometheus는 수동 결과를 1초마다 수집하지만 화면은 기본 5초마다 갱신한다. 2초 간격에서는 화면이 중간 상태를 건너뛸 수 있다. 자세한 설명에는 더 느린 간격이나 그래프·원본 창 기록을 사용한다.

## 6. front-end normality drift 설명

현재 서비스 컨테이너는 Node 10.24.1이며 비교 참조는 저장된 Node 4 정상 캡처다. 버전 차이를 화면의 참조 설명에 표시한다. **현재 LIVE drift 여부와 저장 캡처의 재판정 결과는 별도로 말한다.**

2026-10-23 Ubuntu에서 확인한 저장 캡처 재판정은 다음과 같다. 유효 창만 분모에 넣었고 Node 4/10 파일의 첫·끝 불완전 창은 제외했다.

| 저장 자료 | 유효 창 | 관측된 모델 분류 |
|---|---:|---|
| front-end Node 4 정상 참조 캡처 | 59 | 정상 59 |
| front-end Node 10 변화 비교 캡처 | 59 | 정상 변화 의심 59 |
| catalogue 정상 참조 캡처 | 199 | 정상 199 |

Node 10 첫 유효 창에서는 A가 네 레플리카 모두 0, B가 약 7,606~7,863으로 기준 약 6.05007보다 높고 C는 약 0.11334로 기준 0.2보다 낮았다. 이는 **A 침묵·B 초과·C 안정**이라는 drift 분기를 만족한 근거다.

이 결과는 Node 버전 변경이 유일한 원인이라는 인과 증명이 아니다. 부하·이미지·연결 정책·캡처 조건도 비교해야 한다. 정상 참조 자료를 자기 기준선으로 재판정한 정상 건수 역시 독립적인 오탐률·정확도 평가가 아니다. 현재 LIVE에서 같은 결과가 나오는지는 최신 유효 창으로 따로 확인한다.

## 7. 장애나 발표 종료

Mac 인터넷이 끊겨도 cosmic이 살아 있으면 서버 수집·판정은 계속되며 다른 기기는 같은 주소로 접속할 수 있다. 브라우저 장애, HTTPS 장애, 실제 수집 중단을 구분한다.

LIVE 입력이 멈췄다면 판정 불가를 그대로 보여주고 서버 캡처 모드로 전환한다. “현재 입력을 확인할 수 없어 판정을 유보했고, 이어지는 화면은 저장 자료의 재판정”이라고 설명한다. cosmic 자체가 중단됐다면 서버의 캡처 화면도 사용할 수 없으므로 복구와 별도 시연 자료를 준비한다.

기존 Mac `compose.presentation.yaml`은 운영 장애 때 자동으로 대신 실행되는 구성이 아니다. 필요하면 별도 사전 검증한 로컬 데모로만 사용하고 서버 LIVE와 구분한다. 지금 확장한 15개 캡처·수동 제어가 기본 로컬 데모에 모두 포함됐다고 가정하지 않는다.

발표가 끝나면 수동 작업을 중단하고 브라우저를 닫는다. 이것으로 서버 LIVE나 자동 순환이 멈추지 않는다. 전체 운영 중단은 [서버 운영](server-operations.md)의 명시적 서비스 중지 절차로 수행한다.

발표 기록에는 날짜, 코드 커밋, 선택한 서비스·모드·캡처, 기준선/원본 해시, 원본 창, 데이터 부족 구간, 실제 수행한 검증을 남긴다. 공개 발표 자료에는 서버 자격 증명·원본 명령행·민감 로그를 넣지 않는다.
