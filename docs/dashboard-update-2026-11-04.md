# 레플리카 그림으로 현재 상태 표시 (2026-11-04)

LIVE/캡처 자동 재생과 캡처 수동 재생 대시보드의 판정 흐름 및 요약 카드 행을 제거하고, Grafana 기본 Canvas 패널에 레플리카 4개를 서버 그림으로 표시한다. 추가 플러그인이나 외부 이미지가 필요하지 않다.

- 파랑 `지목 없음`, 주황 `이상 의심`, 회색 `판정 불가`는 모델의 지목 상태다. 공격 확인이나 정상 원인 확정으로 해석하지 않는다.
- 각 그림 아래 두 줄은 해당 레플리카의 비교 탐지기와 시스템콜 빈도 탐지기가 실제 임계값을 넘었는지 표시한다. 전체 이상 의심이어도 개별 초과 여부는 다를 수 있다.
- 정상 변화 의심을 포함한 서비스 분류는 그림 위에 작게 표시한다. 수동 화면은 재생 중·일시정지·완료 등의 제어 상태도 함께 표시한다.
- 입력 부족·수집 단절·없는 선택·재생 종료는 회색으로 표시하고 이전 결과를 현재 정상처럼 남기지 않는다.
- 비교·빈도 그래프와 레플리카별 이벤트/연결 이벤트 작업량, 판정 표·근거·접힌 LIVE 사건 상세를 유지한다. 연구 계산, 임계값, 기준선 및 수집 정책은 변경하지 않는다.

Canvas의 여러 조회 결과를 명확한 필드 이름으로 연결하고, 시각 필드와 수치 필드의 이름이 겹치지 않도록 숫자 필드만 사용한다. 서버 그림은 반응형 열 안에서 84×84 크기를 유지해 상태 문구와 겹치지 않는다. 컨테이너 이름을 정확히 대조하므로 없는 레플리카가 다른 레플리카의 값을 받지 않는다.

## 검증 범위

- Mac과 Ubuntu의 대시보드 검사 15개 통과.
- 실제 Prometheus 조회 301개를 같은 시각의 원본 지표와 대조했다. LIVE 2개, 승인 자동 캡처 15개, 현재 수동 완료 상태, 없는 선택 및 자연적인 입력 회전 중 판정 불가 구간을 포함한다.
- Grafana 13.2.4의 실제 브라우저에서 catalogue/front-end LIVE, 정상 변화 의심 캡처 및 수동 재생 완료 상태를 확인했다.
- 기존 대시보드와 생성기·검사 파일을 서버에 백업하고 화면 파일만 교체했다. 수집기 PID와 8개 컨테이너의 시작 시각·PID·재시작 횟수가 유지되었다.
- 수동 재생을 새로 시작하거나 공격·호스트 재부팅 시험을 수행하지 않는다.
